# 通用时间序列设计

## 1. 背景与目标

`baron-klinecharts` 当前以 `ChartScene v1` 表达单一标的的 OHLC K 线、内置指标、
视口与标注。底层 `klinecharts@10.0.0` 具备自定义 Indicator、多条 line figure、
自定义 Tooltip 和显隐控制能力，但当前发布的 Scene、Adapter 与 Runtime 没有提供普通
多时间序列的正式契约。

本设计新增与 `ChartScene` 并列的 `TimeSeriesScene`，用于在统一时间轴和统一数值轴上
展示一条或多条普通折线。首个业务使用方是 A 股沪市、深市和两市合计成交额，但图表库
不得出现任何市场或成交额专用字段。

本次目标包括：

- 支持多条通用折线及单条显隐。
- 支持明确空值、折线断点和统一十字线 Tooltip。
- 支持替换数据、事件订阅、导出、恢复和销毁。
- 支持 Browser Runtime、无头 Render Runtime 与 Python 入口。
- 保证所有现有 `ChartScene v1` Client API 和行为向后兼容。

本次不包括面积图、柱状图、多 Y 轴、实时增量推送、数据请求、业务指标计算或业务缓存。

## 2. 架构边界

### 2.1 新增独立 Scene

新增 `TimeSeriesScene v1`，不修改 `ChartScene v1` 的字段、约束、校验、运行时入口和
导出语义。两个 Scene 使用独立 Schema 标识和独立解析函数。TimeSeriesScene 的 Schema
标识固定为 `@baron1996/time-series-scene`，Scene 版本固定为 `1`，Time Series Runtime
契约版本固定为 `0.1.0`。承载该能力的 npm 与 PyPI 包目标发布版本为 `0.3.0`，现有
KLine Runtime 的数据契约版本继续保持 `0.2.0`。

TypeScript 新增公开入口：

```ts
parseTimeSeriesScene(input)
createTimeSeriesRuntime(container, scene)
```

现有入口保持不变：

```ts
parseChartScene(input)
createKLineSceneRuntime(container, scene)
```

Python 侧新增下列公开类型与函数，不改变现有 `load_scene`、`save_scene`、
`validate_scene`、`render_scene_html`、`render_scene_png` 的 `ChartScene` 语义：


### 2.2 底层适配

底层 `klinecharts` 强制使用 K 线数据承载时间轴。Time Series Adapter 在内部生成只用于
承载时间戳的零值 OHLC 数据，并将 Candle Pane 完全隐藏。该内部数据不得：

- 从任意业务序列取值或使用一个业务字段替代另一个字段。
- 进入业务 Tooltip、TimeSeriesScene 导出结果或业务回调。
- 参与 Time Series 数值轴范围计算。

每条公开序列映射为一个命名空间隔离的受控内部 Indicator。所有 Indicator 位于同一
Time Series Pane 并共享数值轴。空值不生成对应图形，从而形成折线断点。

内部 Indicator 仅在 `createTimeSeriesRuntime` 初始化时注册；导入模块或创建旧 K 线
Runtime 时不得产生影响旧运行时的全局副作用。

## 3. 数据契约

### 3.1 Scene 结构

`TimeSeriesScene v1` 只允许以下顶层字段，并且全部必填：`schema`、`version`、
`runtime`、`period`、`series`、`data`、`chart`、`viewport`、`render`、`metadata`。
所有 TimeSeriesScene 结构均采用 `additionalProperties: false`，不接受未知字段，也不为
缺失字段提供运行时默认值。

```json
{
  "schema": "@baron1996/time-series-scene",
  "version": 1,
  "runtime": {
    "engine": "klinecharts",
    "engineVersion": "10.0.0",
    "runtimeVersion": "0.1.0"
  },
  "period": { "span": 1, "type": "day" },
  "series": [
    {
      "id": "series-a",
      "name": "Series A",
      "type": "line",
      "unit": "unit",
      "precision": 2,
      "visible": true,
      "style": {
        "color": "rgba(96, 165, 250, 1)",
        "size": 2,
        "style": "solid"
      }
    }
  ],
  "data": [
    {
      "timestamp": 1767225600000,
      "values": { "series-a": 12.34 }
    }
  ],
  "chart": {
    "locale": "zh-CN",
    "timezone": "Asia/Shanghai",
    "layout": {
      "backgroundColor": "rgba(17, 24, 39, 1)",
      "textColor": "rgba(219, 234, 254, 1)",
      "fontFamily": "Baron Sans",
      "fontSize": 12
    },
    "grid": {
      "horizontalColor": "rgba(48, 59, 78, 1)",
      "verticalColor": "rgba(48, 59, 78, 1)"
    },
    "thousandsSeparator": ",",
    "decimalFold": { "enabled": false, "threshold": 4 },
    "zoomAnchor": "cursor",
    "dateFormat": "yyyy-MM-dd",
    "largeNumberFormat": "chinese"
  },
  "viewport": {
    "barSpace": 8,
    "rightOffsetDistance": 24,
    "anchorTimestamp": 1767225600000
  },
  "render": {
    "width": 1280,
    "height": 720,
    "deviceScaleFactor": 1,
    "background": "rgba(17, 24, 39, 1)",
    "fontFamily": "Baron Sans",
    "timeoutMs": 10000
  },
  "metadata": {}
}
```

正式 JSON Schema 复用现有的安全整数、有限数值、RGBA 色值、时间周期、视口、渲染
和 metadata 定义。`chart` 精确复用现有 ChartConfig 中除 `candle` 外的全部字段及约束，
字段均必填且不提供默认值；`viewport`、`render`、`period` 与现有同名结构完全一致。

集合和标量字段采用以下固定约束：

- `series` 长度为 `1..64`；`data` 长度为 `1..1000000`。空数据不构成合法 Scene，
  业务空态不得创建 Runtime。
- `series[].id` 必须满足 `^[A-Za-z][A-Za-z0-9_-]{0,63}$` 且在 Scene 内唯一；
  `name` 长度为 `1..256`；`type` 固定为 `line`。
- `unit` 长度为 `1..64`；`precision` 为 `0..16` 的整数；`visible` 必须显式提供
  布尔值；`style` 必须显式提供 `color`、`size`、`style`，不接受额外字段。
- `data[].timestamp` 为正的安全整数毫秒时间戳，严格递增且不得重复；`values` 必须且
  只能包含 `series` 中声明的全部 `id`。
- `values` 的值只能是有限数字或显式 `null`；不接受字符串、`NaN`、正负无穷，
  也不允许省略某条序列。
- `viewport.anchorTimestamp` 必须精确引用某个 `data` 时间点；其余视口约束与现有
  `ChartScene v1` 一致。
- `metadata` 键数量不超过 64，键长为 `1..128`，值仅允许字符串、有限数字、布尔值
  或 `null`。

### 3.2 序列定义

每条序列包含：

- `id`：Scene 内唯一且稳定的标识。
- `name`：图例与 Tooltip 展示名称。
- `type`：首版固定为 `line`。
- `unit`：坐标和 Tooltip 使用的显示单位。
- `precision`：显示精度。
- `visible`：当前显隐状态，属于可导出的 Scene 状态。
- `style`：直接复用 `common.schema.json#/$defs/lineStyle`，`color`、`size`、`style`
  全部必填，线型只允许 `solid`、`dashed`、`dotted`。

所有序列首版共享一个时间轴和一个线性数值轴，因此同一 Scene 内全部序列的 `unit`
和 `precision` 必须一致，数值轴与 Tooltip 均使用这组单位及精度。多单位、多 Y 轴和
对数轴不在本版本范围内，不能通过 Runtime 猜测或动态切换单位。

### 3.3 时间点与空值

- `data` 的时间戳必须严格递增且不得重复。
- 每个时间点的 `values` 必须显式包含 Scene 中的全部 `series.id`。
- 每个值只能是有限数值或 `null`。
- 未声明的序列 ID、缺失的序列键、`NaN` 和无穷值必须拒绝。
- `null` 必须保留为明确缺失，并产生折线断点；不得被零、前值或其他序列替代。
- 图表库不得派生或计算业务序列。

## 4. Runtime 契约

首版 Runtime 提供：

```ts
export async function createTimeSeriesRuntime(
  container: HTMLElement,
  scene: unknown,
  options?: TimeSeriesRuntimeOptions,
): Promise<TimeSeriesRuntime>;

runtime.setSeriesVisible(
  seriesId: string,
  visible: boolean,
): TimeSeriesScene;

runtime.replaceData(
  data: readonly TimeSeriesPoint[],
): Promise<TimeSeriesScene>;

runtime.exportScene(): TimeSeriesScene;
runtime.subscribe(listener: TimeSeriesRuntimeListener): () => void;
runtime.destroy(): void;
```

公开类型固定为：

```ts
export interface TimeSeriesRuntimeOptions {
  readonly onEvent?: TimeSeriesRuntimeListener;
}

export type TimeSeriesRuntimeEvent =
  TimeSeriesRuntimeEventPayload & TimeSeriesRuntimeEventEnvelope;

export type TimeSeriesRuntimeListener =
  (event: TimeSeriesRuntimeEvent) => void;

export interface TimeSeriesRuntime {
  setSeriesVisible(seriesId: string, visible: boolean): TimeSeriesScene;
  replaceData(data: readonly TimeSeriesPoint[]): Promise<TimeSeriesScene>;
  exportScene(): TimeSeriesScene;
  subscribe(listener: TimeSeriesRuntimeListener): () => void;
  destroy(): void;
}
```

行为约束：

- `setSeriesVisible` 只改变目标序列，并同步更新可导出的 Scene。
- `replaceData` 必须先完整校验新数据；校验失败时保留原数据、锚点和原视图。
- `replaceData` 成功时保留各序列显隐状态、`barSpace` 与 `rightOffsetDistance`，并把
  `anchorTimestamp` 确定性更新为新数据的最后一个时间戳；空数组必须作为非法数据拒绝。
- `exportScene` 返回可重新加载且结果一致的完整 Scene。
- `destroy` 必须移除 DOM、底层 Chart、监听器和 Runtime 内部引用。
- `destroy` 幂等；首次销毁后除重复 `destroy` 外的公开方法统一抛出
  `TimeSeriesSceneError`。
- 未知序列 ID、已销毁 Runtime 上的调用及非法数据必须返回正式错误，不得静默忽略。

事件必须是可 structured-clone 的纯数据，并使用固定 envelope：

```ts
interface TimeSeriesRuntimeEventEnvelope {
  readonly sceneVersion: 1;
  readonly runtimeVersion: '0.1.0';
}

type TimeSeriesRuntimeEventPayload =
  | { readonly type: 'scene-ready'; readonly scene: TimeSeriesScene }
  | {
      readonly type: 'series-visibility-changed';
      readonly seriesId: string;
      readonly visible: boolean;
      readonly scene: TimeSeriesScene;
    }
  | {
      readonly type: 'data-replaced';
      readonly dataCount: number;
      readonly scene: TimeSeriesScene;
    }
  | {
      readonly type: 'crosshair-changed';
      readonly timestamp: number;
      readonly values: Readonly<Record<string, number | null>>;
    }
  | {
      readonly type: 'crosshair-changed';
      readonly timestamp: null;
      readonly values: null;
    }
  | {
      readonly type: 'scene-error';
      readonly issues: readonly TimeSeriesSceneIssue[];
    };
```

`scene-ready` 在 Runtime 完整创建后触发。显隐和数据事件只在操作成功并完成 Scene 更新后
触发。十字线进入或移动到新时间点时发送该点的完整值映射，离开绘图区时发送
`timestamp: null, values: null`。创建阶段校验失败时通过 `options.onEvent` 发送
`scene-error` 后拒绝 Promise；运行期方法失败时先发送 `scene-error`，再同步抛出或拒绝
Promise。`subscribe` 返回的函数用于精确取消该监听器。

时间序列错误使用全新的 `TimeSeriesSceneErrorCode`、`TimeSeriesSceneIssue` 与
`TimeSeriesSceneError`，不得修改或扩展旧 `SceneErrorCode`、`SceneIssue`、`SceneError`。
异常与 `scene-error.issues` 必须使用同一组 `TimeSeriesSceneIssue`。公开错误联合固定为：

```ts
export type TimeSeriesSceneErrorCode =
  | 'TIME_SERIES_SCENE_SCHEMA_INVALID'
  | 'TIME_SERIES_SCENE_VERSION_UNSUPPORTED'
  | 'TIME_SERIES_ENGINE_VERSION_MISMATCH'
  | 'TIME_SERIES_DATA_INVALID'
  | 'TIME_SERIES_UNKNOWN_SERIES'
  | 'TIME_SERIES_RUNTIME_DESTROYED'
  | 'TIME_SERIES_ADAPTER_FAILED'
  | 'TIME_SERIES_EXPORT_INVALID'
  | 'TIME_SERIES_BROWSER_NOT_INSTALLED'
  | 'TIME_SERIES_RENDER_FAILED'
  | 'TIME_SERIES_RENDER_TIMEOUT';
```

错误码和路径固定如下：

- Scene 结构或语义校验失败：`TIME_SERIES_SCENE_SCHEMA_INVALID`，`path` 为最具体的
  JSON Pointer；版本和引擎版本分别使用联合中的专用错误码。
- `replaceData` 输入非法：`TIME_SERIES_DATA_INVALID`，根路径为 `/data`，详细 issue
  使用 `/data/{index}` 或 `/data/{index}/values/{seriesId}`。
- `setSeriesVisible` 收到未知 ID：`TIME_SERIES_UNKNOWN_SERIES`，路径固定为 `/series`。
- Runtime 销毁后调用公开方法：`TIME_SERIES_RUNTIME_DESTROYED`，路径固定为 `/runtime`。
- Adapter 初始化或运行期调用失败：统一包装为 `TimeSeriesSceneError`，错误码
  `TIME_SERIES_ADAPTER_FAILED`，路径固定为 `/runtime/adapter`，不得泄漏底层异常类型。
- 导出状态无法通过校验：`TIME_SERIES_EXPORT_INVALID`，路径固定为 `/`。
- 无头渲染缺少浏览器、初始化失败或超时分别使用 `TIME_SERIES_BROWSER_NOT_INSTALLED`、
  `TIME_SERIES_RENDER_FAILED` 与 `TIME_SERIES_RENDER_TIMEOUT`，路径固定为 `/render`。桥接对象出现
  与 Runtime ready 共用一个 deadline，只有 deadline 实际耗尽才返回超时。

Python 侧新增同名 `TimeSeriesSceneError` 与字符串错误码，不复用或改变现有 `SceneError`
的类型语义。

## 5. 图例与 Tooltip

Runtime 负责图内图例和十字线 Tooltip 的一致行为：

- 图例按 `series` 声明顺序展示。
- 图例可以触发单条显隐，并通过 Runtime 正式 API 更新状态。
- 十字线定位到一个统一时间点后，按照声明顺序输出所有序列。
- `null` 显示为明确缺失标记，不显示为零。
- 值使用 Scene 内统一声明的 `unit` 与 `precision` 格式化。
- 隐藏序列不绘制折线；Tooltip 是否展示隐藏序列应固定为“不展示”，避免界面语义冲突。
- 图例由 Runtime 在图表容器内渲染；无头 Runtime 使用相同 DOM 和样式生成视觉产物。
- 全部序列隐藏，或所有可见序列在当前数据中均为 `null` 时，Time Series Pane 保持空白，
  数值轴不显示刻度标签；内部零值 OHLC 不得进入自动范围。重新出现可见有限值后，
  数值轴只基于这些值重新计算。

## 6. 错误处理

- Schema 错误：返回路径明确的 Scene 校验错误。
- Adapter 映射错误：返回正式 Adapter 错误，不创建部分 Runtime。
- 数据替换错误：原 Runtime 保持可用且数据不变。
- Render Runtime 超时或渲染失败：保持现有错误模型，不输出不完整制品。
- 不提供其他图表引擎或业务侧 Canvas 绘制作为 fallback。

## 7. 向后兼容

本版本是纯新增能力：

- `ChartScene v1` JSON Schema 不变。
- 现有 TypeScript 与 Python API 签名不变。
- 现有指标、Overlay、视口、导出和事件语义不变。
- `klinecharts` 依赖继续固定为 `10.0.0`。
- 旧 Scene 不迁移、不自动转成 TimeSeriesScene。
- 新 Indicator 注册不得污染旧 K 线 Runtime。

如实现需要改变上述任一兼容条件，必须暂停并重新获得用户确认。

## 8. 测试与发布门禁

### 8.1 新能力测试

- Schema 正常、边界和非法输入测试。
- 重复时间戳、序列键不完整、未知键、非法数值和空值测试。
- 三线绘制、断点、单条显隐、Tooltip 和数值轴测试。
- `replaceData` 原子性、事件、导出恢复和销毁测试。
- Browser Runtime 与无头 Render Runtime 的视觉基线。
- TypeScript/Python 跨语言校验与序列化一致性测试。

### 8.2 旧能力回归

- 全部现有单元、浏览器、渲染、安装和跨语言测试。
- 旧 `ChartScene v1` fixtures、canonical hash 和截图基线。
- 旧公开 API 的 TypeScript 编译契约测试。
- 旧公开 export/type 声明快照逐字保持一致；新导出使用独立的 Time Series 类型快照，
  不向任何旧封闭联合类型增加成员。

### 8.3 发布

- npm 与 PyPI 均构建明确版本候选产物。
- 安装测试必须从打包产物执行，不得引用仓库源码。
- 发布完成后验证 registry 中的正式版本和独立安装。
- 下游业务只能精确依赖正式版本并提交自己的 lockfile。
