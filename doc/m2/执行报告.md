## 3. 根因、RED 与最小修复

### 3.1 根因

`Runtime.updateOverlay()` 同步更新 Adapter committed Scene 后，KLineCharts 的异步绘制命中区域仍可能短暂保留旧几何。用户立即点击新主体时，Adapter capture-phase 的当前规范几何命中先写入选择；引擎随后按旧命中区域把同一次点击解释为空白并触发 `onDeselected`，旧实现无条件把同一 Overlay 选择清空。

该竞争不是 OIDC、GitHub Release、固定 macOS 坐标或单一 Node 版本问题：候选 `370ffcc1` 在本机 Node 25 重复 5 次为 4 PASS/1 FAIL，在 Node 22 重复 10 次为 9 PASS/1 FAIL；两帧诊断等待 20/20 通过只用于确认时序根因，未进入正式产品或测试修复。

### 3.2 RED

新增 `packages/klinecharts-adapter/test/selection-arbitration.spec.ts`，先导入尚不存在的仲裁实现并确认失败。冻结四条边界：

- programmatic update 后，回调坐标仍命中当前选中 Overlay 的规范几何时视为 stale deselect；
- 真正空白坐标不得被忽略；
- 命中其他 Overlay 不得被忽略，后续选择可正常切换；
- 回调缺少有限坐标时保持既有 deselect 语义。

### 3.3 修复

新增内部纯函数 `shouldIgnoreStaleOverlayDeselection`。Adapter `onDeselected` 仅在回调提供有限 `x/y` 且该 CSS 像素坐标按当前规范几何仍命中同一个已选 Overlay 时忽略旧引擎回调。坐标命中为空、命中其他 Overlay、当前选择已变化或坐标缺失时均不忽略，因此不会吞掉真实空白取消或其他 Overlay 切换。

诊断确认 KLineCharts 回调坐标与 Adapter 容器 CSS 像素坐标一致；示例回调 `(891, 305)` 命中当前 `overlay-segment-0` 主体。临时诊断日志已删除。修复没有改变 Scene Schema、Runtime API/事件协议，也没有禁用引擎 deselect；产品代码没有 sleep、timeout 或 `requestAnimationFrame` 等待。
