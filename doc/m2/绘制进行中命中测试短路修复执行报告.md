# baron-klinecharts 绘制进行中命中测试短路修复执行报告

## 1. 结论

**READY_FOR_RELEASE_0.4.2**

klinecharts 10.0.0 下“绘制进行中点击被已有受控 overlay 拖拽命中断言消费”的问题已修复并完成本地全量验证。修复提交为 `c0aa5ea3c954905b397f19e69f26415a7bf10977`，随后将版本从 `0.4.1` 统一提升至 `0.4.2` 并发布。

Scene `version` 保持 `1`，`ChartScene.runtime.runtimeVersion` 保持协议版本 `0.2.0`，事件 envelope `{ sceneVersion: 1, runtimeVersion: "0.2.0" }`、schema enum 与 fixture 均未变化。本次不修改 my-cage，不在实现或测试中加入等待、延时、放慢点击节奏或降低命中阈值等绕过，未使用任何 fallback。

## 2. 背景与根因

0.4.1 已修复 klinecharts 10.0.0 的 500ms 点击仲裁吞掉快速连续绘制第二条水平线首击的问题（commit `2892278a8100bfd53d24d1eeff6ebc6093cefab6`），my-cage 升级到 0.4.1 后腾讯云 M2 组合旅程仍失败。经事件级定位，失败是另一个独立缺陷，与 500ms 仲裁无关：

- 一条水平线绘制完成并被 `updateOverlay` 重定价后，若紧接着开始新绘制，新绘制的首击落在距该已有水平线 ≤12px（`OVERLAY_BODY_HIT_THRESHOLD_CSS_PX`）范围内；
- `KLineChartsSceneAdapter.#handlePointerDown`（容器 capture 阶段）的命中测试把该次点击判定为对已有受控 overlay（`horizontalStraightLine` / `priceMeasurement`，见 `isControlledInteractionOverlay`）的拖拽；
- adapter 执行 `preventDefault` + `stopImmediatePropagation` + `setPointerCapture(container)`，引擎收不到 `mousedown`，而 klinecharts 10.0.0 的 step 绘制依赖 `mouseClickEvent` 推进并完成，新绘制首击被消费，第二条线无法创建。

真实浏览器事件证据：

- 成功点击：`pointerdown → mousedown → pointerup → mouseup → click`，全部落在 canvas；
- 失败点击：`pointerdown` 落在 canvas 后 `mousedown/mouseup` 未派发，`pointerup/click` 被重定向到 adapter 容器（`setPointerCapture` 特征）。

## 3. RED 复现

在 `packages/web-runtime/test/runtime.browser.spec.ts` 新增真实浏览器回归测试，完整复现用户路径且不修改 my-cage：

1. `startOverlayDrawing('priceMeasurement')`，两次点击完成量度；
2. `startOverlayDrawing('horizontalStraightLine')`，一次点击完成水平线；
3. `updateOverlay` 重定价该线；
4. 再次 `startOverlayDrawing('horizontalStraightLine')`，在距重定价后该线 6–12px（≤12px 阈值）处点击，断言第二条水平线创建。

测试在页面内以 capture 监听记录 4 次点击的 `mousedown/mouseup` 时间戳与坐标。修复前该测试失败：末次点击的 `mousedown/mouseup` 被 `preventDefault` 抑制（stamps 仅 6 条），`createdIds` 缺第二条水平线。测试不包含任何等待或延时。

## 4. 修复方案与影响

修复位置在适配层（`packages/klinecharts-adapter/src/adapter.ts`）：

- 新增 `#drawingInProgressId` 状态（与引擎 progress overlay 对齐）：`startOverlayDrawing` / `startDrawing` 成功创建 progress overlay 后置位；`onDrawEnd`（引擎完成绘制）或 `onRemoved`（绘制被移除）按 overlay id 清位；量度手动完成路径 `#completeInteractivePriceMeasurement` 与 `dispose` 同步复位。
- `#handlePointerDown` 在量度处理块之后、`hitTestOverlayGeometries` 之前短路返回：绘制进行中不触发对已有 overlay 的命中测试、选中、取消选中或拖拽，也不执行 `preventDefault` / `stopImmediatePropagation` / `setPointerCapture`，事件完整交还引擎；绘制完成后恢复既有拖拽与选择行为。

兼容边界不变：Scene schema `@baron1996/kline-scene` version=1、Runtime protocol 0.2.0、engine 10.0.0、事件 envelope 不变，已发布公共 API 签名不变；0.4.1 的 `startOverlayDrawing` 点击仲裁显式复位逻辑（`resetClickArbitration`）原样保留。离线 HTML 与 Python 嵌入运行时模板已重新生成并同步本次修复。

## 5. 验证证据

验证环境：macOS，Node.js 22.12.0，npm 10.8.2，Playwright 1.61.0 / Chromium，Python 3.12。

- 完整 `npm run verify` 退出码 0：generate 幂等、typecheck、mock、单元测试、真实 headless Chromium 浏览器测试（根套件 10 项、adapter 116 项、web-runtime 129 项、render-runtime）、渲染基线、Python、跨语言、安装门禁与 `npm audit --omit=dev` 0 漏洞全部通过；
- 新增回归测试在修复前失败（第 4 次点击 mousedown/mouseup 被抑制、第二条水平线未创建）、修复后通过；
- 0.4.1 的“500ms 内快速连画两条水平线”回归用例继续通过；既有拖拽、选中、量度相关浏览器用例全部保持通过；
- `npm run generate` 二次运行无新增改动；
- 版本提升至 `0.4.2` 后完整 `npm run verify` 通过，`release:check-version --tag v0.4.2` 确认发布目标。
