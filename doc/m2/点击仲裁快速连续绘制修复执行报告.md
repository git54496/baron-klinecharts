# baron-klinecharts 点击仲裁快速连续绘制修复执行报告

## 1. 结论

**READY_FOR_RELEASE_0.4.1**

klinecharts 10.0.0 点击仲裁吞掉“快速连续绘制第二条水平线首击”的问题已修复并完成本地全量验证。修复提交为 `2892278a8100bfd53d24d1eeff6ebc6093cefab6`，随后将版本从 `0.4.0` 统一提升至 `0.4.1` 并发布。

Scene `version` 保持 `1`，`ChartScene.runtime.runtimeVersion` 保持协议版本 `0.2.0`，既有事件协议、schema enum 与 fixture 均未变化。本次不修改 my-cage，不在测试或调用方加入等待或延时。

## 2. 背景与根因

my-cage M2（价位确认与结构回放）在腾讯云 Task 7 组合验证时，价格量度完成后绘制第一条水平线（颈线）成功并已写库，但紧接着绘制第二条水平线（目标线）时，单击 30 秒不产生 overlay。底层引擎 klinecharts 10.0.0 的点击仲裁逻辑位于 `dist/index.esm.js` 的 `EventHandlerImp._mouseUpHandler`：

- 每次 mousedown 启动 500ms 定时器（`Delay.ResetClick = 500`）；
- 下一次 mouseup 若落在 500ms 窗口内，且与上次点击的曼哈顿距离 ≥ 5px（`ManhattanDistance.DoubleClick = 5`），引擎既不派发 `mouseClickEvent` 也不派发 `mouseDoubleClickEvent`，直接丢弃这次点击；
- `horizontalStraightLine`（`totalStep = 2`，首击即完成）的提交点击会激活该窗口，用户在 500ms 内紧接着画第二条线时，首击被引擎丢弃，而绘制步进完全依赖 `mouseClickEvent`。

0.2.3 的修复只是让量度完成时顺带复位了点击状态，因此“量度 → 第一条水平线”成功，但“水平线 → 水平线”快速连续绘制仍然失败；registry 上的 0.3.0 与 0.4.0 均存在同样问题。

## 3. RED 复现

在 `packages/web-runtime/test/runtime.browser.spec.ts` 新增浏览器回归测试：同 Runtime 内连续绘制两条水平线，两次点击间隔 < 500ms、坐标相距 ≥ 50px，断言两条 overlay 都创建、`overlay-created` 事件完整且无 `scene-error`。

测试在页面内记录 `mousedown/mouseup` 时间戳与坐标并显式断言落在仲裁窗口内（`mouseup₂ − mousedown₁ < 500ms`、距离 ≥ 50px），防止通过放慢点击节奏绕过。修复前该测试失败：`createdIds` 只有第一条水平线，第二条首击被吞。

## 4. 修复方案与影响

修复位置在适配层（`packages/klinecharts-adapter`）：

- `src/engine.ts`：`EngineHandle` 新增 `resetClickArbitration` 句柄，读取 klinecharts 10.0.0 私有 `ChartImp._chartEvent._event._resetClickTimeout`。引擎未提供任何公开复位 API，评估过 vendor 整份引擎的方案，但为控制改动面与维护成本选择最小侵入：句柄由 `KLINECHARTS_ENGINE_VERSION` 运行时断言保护，若引擎私有结构变化，初始化显式抛出 `RUNTIME_INIT_FAILED` 而非静默降级。
- `src/adapter.ts`：`startOverlayDrawing` 在每次新绘制开始前显式调用复位，保证新绘制首击总是独立的单击。

影响边界：不改变引擎对双击的语义（同点双击仍触发 `mouseDoubleClickEvent`），不影响多步绘制的既有行为，不修改任何公共 API、协议或事件格式；量度、Workspace、时间序列等既有测试全部保持通过。

## 5. 验证证据

验证环境：macOS，Node.js 22.12.0，npm 10.9.0，Playwright 1.61.0 / Chromium，Python 3.12。

- 完整 `npm run verify` 退出码 0：typecheck、mock、单元测试、真实 headless Chromium 浏览器测试（web-runtime 128 项、adapter 116 项）、渲染基线、Python、跨语言、安装门禁与 audit 0 漏洞全部通过；
- 新增回归测试在修复前失败、修复后通过，且重复执行 10/10 稳定；
- `npm run generate` 幂等：二次生成无新增改动，离线 HTML 与 Python 嵌入运行时产物已随修复同步；
- 版本提升至 `0.4.1` 后再次完整 `npm run verify` 通过，`release:check-version --tag v0.4.1` 确认发布目标为四个公共 npm 包与 PyPI `baron-klinecharts`。
