## 4. 价格轴契约校准

### 4.1 正确归属

价格轴模式应扩展现有：

```text
ChartScene.panes[].yAxes[]
```

不应添加到 `ChartScene.chart`，也不应另造只服务 `my-cage` 的 chart-config 配置。
原因是 Scene 已经以稳定 YAxis ID 表达 pane 与轴的关系，Adapter 的
`conversion/panes.ts` 也正是在该层调用 KLineCharts `createYAxis/overrideYAxis`。

建议冻结字段：

```json
{
  "id": "axis-price",
  "role": "primary",
  "scale": "logarithmic"
}
```

允许值：

- `linear` → KLineCharts `normal`
- `logarithmic` → KLineCharts `logarithm`

为兼容 M1，`scale` 在 Scene version 1 的结构层可以是可选字段；缺失只表示旧 M1
Scene，并按唯一兼容规则解释为 `linear`。所有 M2 fixture 和 Runtime 新建/修改后的 Scene
必须显式写出 `scale`，不得依赖引擎默认值。

### 4.2 非正价格规则

M2 的 logarithmic price axis 必须在进入引擎前明确拒绝非正价格：

- candle pane 的 open/high/low/close 必须全部 `> 0`；
- 位于该 pane、含 value 数据坐标的 Overlay，其所有价格锚点必须 `> 0`；
- `priceMeasurement` 的两个价格锚点在任何轴模式下都必须 `> 0`，因为百分比以起点为分母；
- Runtime 从 linear 切到 logarithmic 前必须对当前完整 Scene 做相同校验；
- 拖动若产生 `<= 0`，必须取消并恢复最后一个已提交 Scene，发出明确错误；
- 禁止静默切回 linear、钳制为 epsilon 或删除非法 Overlay。

M2 只要求 candle 主价格轴支持 linear/logarithmic。指标 pane 的对数语义不应顺带扩张，
除非后续目标单独确认。

### 4.3 固定业务价位不变的验证方式

“价格不变”必须在数据层证明，不能只做截图对比。建议以同一 M2 fixture 和同一个稳定
水平线 ID 执行以下断言：

1. 在线性轴创建 Runtime，记录水平线 `anchor.value`、ID、styles、metadata，以及只包含
   overlays 的 canonical projection hash；同时记录该数据价格映射出的屏幕 Y 坐标。
2. 调用公开 Runtime API 切换为 logarithmic，确认屏幕 Y 坐标发生符合对数映射的变化，
   但 `getOverlay`、`listOverlays`、`exportScene` 中的价格、ID、styles、metadata 和 overlay
   projection hash 完全不变。
3. 在 logarithmic Scene 上执行 export → destroy → recreate，确认完整 canonical Scene hash
   保持不变；这证明恢复没有依赖运行时默认值。
4. 再切回 linear，确认完整 Scene（包括 axis scale）回到初始 canonical hash。

完整 Scene hash 在 linear 与 logarithmic 之间**理应不同**，因为 `yAxes[].scale` 是正式
Scene 内容；不能错误要求切轴前后整个 Scene hash 相等。真正必须恒定的是价格数据及其
Overlay 投影，像素值只用于证明显示映射确实变化，绝不写入 Scene。

## 5. 量度工具最小契约建议

建议正式 Overlay type 使用：

```text
priceMeasurement
```

最小 Scene 数据只保存：

- 通用 Overlay 基础字段；
- `start: { timestamp, value }`；
- `end: { timestamp, value }`；
- 既有 `styles`；
- 可选 opaque `metadata`。

以下派生读数不写入 Scene，避免重复事实和 canonical 漂移：

```text
absoluteChange = end.value - start.value
percentageChange = absoluteChange / start.value * 100
```

建议 Task 1 冻结的显示规则：

- 起止价格和绝对变化按 `symbol.pricePrecision`；
- 百分比固定两位小数并带 `%`；
- 正值显式 `+`，零值显示 `0.00%`，负值显式 `-`；
- linear/logarithmic 都以原始数据值计算，不能从像素距离反推读数；
- export/recreate 后由相同锚点重新计算出相同读数。

建议唯一整体移动语义冻结为 **保持绝对价格差**：两个时间锚点按相同 bar-index 差移动，
两个价格锚点增加相同价格差。该语义符合 M2 水平量度高度，并与引擎当前基础移动模型一致。
不同时支持隐式“保持百分比”模式；若以后需要比例刚体移动，应作为新的显式契约设计。

## 6. 精确命中、编辑与事件建议

### 6.1 命中规则

当前引擎内部 2 px/5 px 值过小且不是本仓公开承诺。结合 M1 已留给 M2 的
“12px/14px 精确命中”目标，建议 Task 1 冻结：

- 线主体：距离不超过 12 CSS px 命中；13 px 不命中；
- 锚点：中心距离不超过 14 CSS px 命中；15 px 不命中；
- 锚点命中优先于主体命中；
- 多 Overlay 重叠时先取最高 `zLevel`，相同 `zLevel` 取 Scene 数组中后出现者；
- 阈值使用 CSS px，不随 devicePixelRatio 改变；
- resize、滚动、缩放和 linear/logarithmic 切换后保持相同规则。

这些阈值尚未实现，必须通过受控 project extension 或等价正式扩展点完成，不能依赖
KLineCharts 打包产物中的私有常量。

### 6.2 过程事件

建议事件契约至少区分：

- `overlay-created`
- `overlay-selection-changed`，允许 `id: null`
- `overlay-drag-started`
- `overlay-dragging`
- `overlay-drag-committed`
- `overlay-drag-cancelled`
- `overlay-style-changed`
- `overlay-delete-requested`
- `overlay-removed`
- `host-action-requested`
- `scene-error`

现有 M1 的 committed events 保持兼容；不得把 `overlay-updated` 改成高频 progress 事件。
新增过程事件承载尚未提交的数据快照，只有 committed 事件才能更新可导出的 Scene。
`overlay-selection-changed` 必须覆盖 deselect，因为当前 Runtime 只有 selected 回调，点击空白后
可能保留陈旧的 `selectedOverlayId`。

拖动事件应包含稳定 Overlay ID、`interactionId`、目标 `body | anchor`、可选 anchor index、
数据坐标、Scene version 和 Runtime 协议版本。事件只携带结构化克隆的纯数据，不暴露
KLineCharts Chart、figure 或 DOM 对象。

Escape、失焦、销毁和 Scene 重载必须收敛活动事务：取消时恢复最后一个已提交 Scene，
并在事件总线清理前发出一次 cancelled/error。`host-action-requested` 的 `action` 只能是
通用动作标识；正式图表契约不得出现 `neckline`、`target_price`、`price_version`、
`structure_id` 或 `confirmed`。

删除边界建议冻结为：`overlay-delete-requested` 只发请求、不先删除；宿主成功处理后再调用
既有 `removeOverlay`，由后者发 `overlay-removed`。为保持 M1 兼容，程序化 `removeOverlay`
仍是直接删除 API。标准工具栏在 M2 下如何从旧的“直接删除”迁移到“请求删除”，必须由
Task 1 明确一个可判定的配置/API 规则，不能同时存在未声明的隐式行为。归档属于宿主业务，
Runtime 只认识删除请求和 opaque `actionId`。

### 6.3 样式编辑边界

现有 Scene styles 已足够 M2 最小范围，不需要重设计完整样式矩阵。后续只需：

- 颜色编辑；
- 线宽编辑；
- solid/dashed/dotted 编辑；
- 样式变化只改变 styles，不改变 ID、锚点、paneId 或 metadata；
- 工具栏复用现有选中状态和 `updateOverlay`，补最小编辑控件与独立事件。

## 7. Schema 与版本建议

### 7.1 Scene/Runtime 协议

建议：

- `ChartScene.version` 保持 `1`；
- `runtime.runtimeVersion` 新增 `0.2.0`；
- 新 Runtime 接受旧 M1 `0.1.0` Scene 和新 M2 `0.2.0` Scene；
- M2 的 `scale`、`priceMeasurement` 和新交互契约必须输出 `runtimeVersion: "0.2.0"`；
- 语义校验必须拒绝把 M2 字段伪装在 `runtimeVersion: "0.1.0"` 中；
- 旧 Runtime 会因为旧 Schema 的 additionalProperties/enum/RuntimeIdentity 限制明确拒绝
  M2 Scene，不会静默错误解释；
- 旧 M1 Scene 的 canonical bytes/hash 在未迁移、未修改时保持不变。

这是一组向后兼容读取、向前明确拒绝的扩展，不需要仅为 M2 增加 Scene version 2。
若 Task 1 无法用上述规则同时证明 M1 hash 不变和旧 Runtime 明确拒绝，则必须停止并重新
评估 Scene version，而不是强行实现。

### 7.2 包版本

M2 是公开功能新增，建议使用统一 minor 版本，而不是继续追加零散 patch：

| 对象 | 建议版本 |

| 根发布协调版本 | `0.2.0` |

| Adapter | `0.2.0` |
| Web Runtime | `0.2.0` |

Schema、语义校验和 canonical fixture 同步。最终发布版本仍须在发布候选门前重新查询
npm、PyPI、tag 和 Release，本文不声明 `0.2.0` 已被保留或仍未占用。
