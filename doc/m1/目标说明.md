## 1. 本仓在 M1 中要得到什么

M1 的用户结果是：用户在腾讯云 `my-cage` 中查看一个真实标的的日 K，画一条水平参考线，并在刷新、重新登录和重新打开详情后看到同一条线。

`baron-klinecharts` 本轮只负责让这段旅程具备正式图表能力：

- 使用唯一 KLineCharts 引擎显示日线蜡烛图；
- 创建、选择和删除水平参考线；
- 为参考线分配稳定 Overlay ID；
- 使用价格等数据坐标持久化，不保存像素坐标或数组索引；
- 将完整 Scene 确定导出；
- 从导出 Scene 重建后恢复同一参考线；
- 通过标准工具栏完成 M1 操作；
- 发布可从公共 registry 安装的正式版本、tag 和 Release。

M1 不要求一次完成 `my-cage` 的全部图表终态能力。对数/线性、量度工具、完整正式线型、精确命中、过程级对数拖动、全屏、折线图和完整样式矩阵留到 M2/M3。

当前仓库已经具备：

- `horizontalStraightLine` 等 Overlay；
- 稳定 Overlay ID 映射；
- 数据坐标 Scene；
- Overlay 创建、更新、删除、选择事件；
- Scene 导入和导出；
- 标准工具栏；
- 离线 HTML、CLI、Python 和渲染产物；
- 单元、浏览器、渲染、跨语言和安装测试；
- npm/PyPI/GitHub Release 工作流及制品构建脚本。

当前 M1 缺口不是重建这些能力，而是：

- 冻结“蜡烛图 + 水平参考线 + round-trip”最小正式契约；
- 证明 Runtime 和标准工具栏的真实浏览器旅程；
- 证明页面刷新所需的 export → destroy → recreate 行为；
- 确认 Scene hash 稳定；
- 形成公共 registry 正式版本；
- 形成 Git tag 和 GitHub Release；
- 在干净消费者工程中从 registry 黑盒安装。

### 2.1 已确认的 M1 图表决策

用户已经确认以下产品与契约选择：

- npm/Python 首发候选版本统一为 `0.1.0`，正式发布前必须重新检查 registry；
- Scene version 为 `1`；
- Runtime version 为 `0.1`；
- 正式水平参考线类型为 `horizontalStraightLine`；
- 水平线只允许有限数值 `anchor.value`，拒绝无意义 `timestamp`；
- 默认样式沿用现有蓝色 `rgba(41, 98, 255, 1)`、`1px`、`solid`。

这些确认只关闭产品与契约选择，不代表 GitHub Environment、保护规则和审批人、npm 组织权限与 2FA、npm token/OIDC、PyPI Trusted Publisher/OIDC、registry 发布前复查或任何 tag、Release、npm/PyPI 发布已经完成或获得授权。

## 3. M1 正式图表契约

### 3.1 蜡烛图

M1 只要求：

- 日线数据可以按 ChartScene market data schema 加载；
- 蜡烛样式来自 Scene；
- 数据按 timestamp 排序并保持 OHLC；
- 图表不请求网络，不理解标的上游；
- 相同 Scene 重建产生相同数据和 Overlay 状态。

本仓不负责把 `fxxking-data` 响应转换为 Scene；转换和页面装配属于 `my-cage`。

### 3.2 水平参考线

M1 使用已经确认的正式水平直线类型 `horizontalStraightLine`。

契约要求：

- 稳定 `id`；
- candle pane 的稳定 `paneId`；
- 有限数值的价格 `value` 数据坐标；
- visible、locked、zLevel、mode 和 styles；
- 可选不透明 metadata；
- 创建、选择、删除；
- export/recreate 后 ID、价格、样式和 metadata 不变。

水平直线的锚点必须严格为有限数值 `anchor.value`；任何无意义 `timestamp` 都应被拒绝。它禁止保存屏幕像素或 K 线数组索引。

### 3.3 Scene 导出与恢复

M1 必须证明：

1. 解析输入 Scene；
2. 创建 Runtime；
3. 绘制水平参考线；
4. 导出完整 Scene；
5. canonicalize 并计算稳定 hash；
6. 销毁 Runtime；
7. 从导出 Scene 创建新 Runtime；
8. 找回相同 Overlay；
9. 再次导出得到相同图表语义。

Runtime 不负责数据库持久化。`my-cage` 保存和读取 Scene 或 Drawing 数据。

### 3.4 标准工具栏

M1 工具栏只需正式支持：

- 选择水平参考线工具；
- 当前选择删除；
- Scene 导出；
- 与图表平移/缩放不冲突；
- 键盘和触摸基础可用。

M1 不增加“确认”业务按钮。价位确认在 M2 通过通用宿主动作边界设计。

## 7. 阶段门

### BK-M1-0：校准门

- registry 现状已重新检查；
- 首发候选版本 `0.1.0`、Scene version `1` 和 Runtime version `0.1` 已确认；
- M1 水平线类型、有限数值 `anchor.value` 和默认样式已确认；
- Task 1 开始前已获得用户单独明确授权；
- GitHub/npm/PyPI 外部发布条件在发布门禁重新核验；
- tag、Release 和 npm/PyPI 发布分别获得明确授权。

### BK-M1-1：Scene 门

- 蜡烛图和水平参考线通过 Schema/semantic/canonical 测试；
- Overlay ID 和 value 坐标稳定；
- 旧 fixture 不被无意破坏。

### BK-M1-2：Runtime 门

- 工具栏创建水平参考线；
- 选择和删除通过；
- export/destroy/recreate 通过；
- 重建后 ID、value、style 和 metadata 一致；
- destroy 无监听器和 DOM 泄漏。

### BK-M1-3：制品门

- `npm run verify` 全绿；
- 公共 tarball 和 Python 制品通过；
- 无 workspace link、本地路径、测试产物或秘密；
- 干净环境安装通过。

### BK-M1-4：正式发布门

- npm/PyPI/tag/Release 版本一致；
- registry 安装通过；
- `my-cage` lockfile 固定精确版本；
- 消费者黑盒只使用公开 API。

## 8. 必须停止并回报的情况

- 版本已被 registry 占用；
- 发布凭据、2FA、Environment 或 Trusted Publisher 未确认；
- M1 需要修改 Scene 破坏性契约但没有迁移结论；
- 水平参考线 round-trip 改变 ID 或价格；
- 需要保存像素坐标才能恢复；
- 工具栏只能通过消费者私有 DOM 补丁完成；
- 发布制品含 workspace link 或本地源码引用；
- `my-cage` 要求图表仓理解价位确认；
- 全量回归失败；
- 发布、tag 或 Release 尚未获得授权。

发生以上情况时停止，不增加第二引擎或 fallback。
