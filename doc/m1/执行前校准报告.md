### 3.1 蜡烛图

当前实现已经满足 M1 对蜡烛图的底层要求：

- 使用唯一允许的 KLineCharts 引擎，不存在第二图表引擎或 fallback。
- Web Runtime 能将输入的 OHLCV 数据加载到图表。
- 已有浏览器与渲染测试覆盖基础图表加载。
- M1 不需要重新实现 candle renderer。

剩余工作属于证据建设：使用 M1 的真实标的 fixture 验证预期的 symbol/timeframe 数据能进入既有蜡烛图链路。

### 3.2 `horizontalStraightLine` 正式 Scene 契约

水平直线的正式 Scene 记录应包含：

- 稳定且唯一的 `id`。
- `type: "horizontalStraightLine"`。
- 对应 candle pane 的 `paneId`。
- 唯一有业务意义的锚点：`anchor: { value: <finite number> }`。
- `visible`、`locked`、`zLevel`、`mode`。
- 完整 `styles`。
- 可选 `groupId`。
- JSON 兼容的可选 `metadata`。

正式契约不应包含：

- `timestamp`：水平无限直线不依赖横轴时间位置。
- 屏幕像素坐标。
- 数据数组索引。
- 其他只能在单次运行中成立的临时状态。

正常创建和导出路径已经只输出 `{ value }`。实际缺口位于：

- `packages/scene-schema/src/semantic-validator.ts`
- 对应的 Python Scene 语义校验实现

两端目前都应补充负向规则：当 `horizontalStraightLine.anchor` 含有 `timestamp` 时拒绝该 Scene，确保 TypeScript 和 Python 契约一致。

### 3.3 Stable ID 与确定性恢复

浏览器诊断覆盖了以下生命周期：

1. 通过工具栏创建水平直线。
2. 获得 ID `overlay-horizontalStraightLine-0`。
3. 导出 Scene。
4. 销毁运行时。
5. 使用导出的 Scene 重建。
6. 再次导出并比较 ID、语义字段和 canonical hash。
7. 重建后重新选择并删除该 Overlay。

诊断结果：

- 创建、首次导出、销毁和重建后的 Overlay ID 一致。
- `paneId`、`styles`、`metadata`、`visible`、`locked`、`zLevel`、`mode` 均保持一致。
- 锚点只有 `value`，没有 `timestamp`。
- Scene version 为 `1`。
- Runtime version 为 `0.1`。
- 销毁前后 canonical hash 均为：

  `5e077dcf2aeb0cf27f786072a92239987691e9cce7ef24d7a5c55d6a5784339b`

- 重建后的选择和删除均成功。

Scene 是恢复行为的权威来源；canonical hash 用于验证规范化后的 Scene 身份一致，不应被误解为单独承担恢复职责。
