# 同标的跨周期画线实施计划

## 1. 实施目标与权威边界

本计划以《全图表统一画图能力技术方案》为唯一上位架构。跨周期能力只在现有
`DrawingDocument`、`DrawableWorkspaceDocument`、`DrawingProjectionService` 和
`DrawableWorkspaceRuntime` 之上增加宿主编排，不新增或复制 Drawing 几何、Schema、
Canonical、投影算法、画线 Runtime、Adapter 或图表引擎。

本次交付包含：

- 显式稳定标的 `instrumentKey` 到 `scopeKey` 的绑定校验；
- 宿主注入的周期 Scene 加载与同 kind 原地切换；
- `host-confirmed` Drawing 候选的持久化、哈希确认、提交或拒绝编排；
- revision、幂等键、业务 pending 状态和失败恢复所需的协调边界；
- ChartScene 与 TimeSeriesScene 共用同一套编排，不裁剪 22 种 Drawing；
- 不改变 Legacy `ChartScene.overlays`、旧 Scene Runtime 和旧导出制品。

本次不实现行情网络请求、数据库、owner/权限/审计服务，也不把这些业务字段写进
Drawing 或 Workspace。行情 Scene 必须由宿主通过注入端口装配；金融行情数据来源由
宿主保证经过 `fxxking-data`。

## 2. 执行前发现的公共能力缺口

现有 `DrawableWorkspaceRuntime.replaceScene()` 已能让 Adapter 原子替换 Scene，但
`DrawingSessionController` 的投影 Scene 仍固定为 Runtime 创建时的初始值，且切换过程
没有进入 `reprojecting` 状态。跨周期切换后新产生的 Drawing 候选可能继续使用旧周期
Scene 做投影校验。

该缺口必须先在统一画图公共层修复：

- Controller 持有可更新的当前投影 Scene；
- Scene 替换前以 confirmed Drawing 全量验证候选 Scene；
- 同步替换期间进入 `reprojecting` 并禁止 Drawing mutation；
- Adapter 替换失败时恢复 `ready`，保留旧投影 Scene 和 confirmed Drawing；
- 替换成功后才同时提升 Runtime Scene 与 Controller 投影 Scene；
- 不暴露 Chart，不让协调器访问 Adapter 或 Projection Service。

## 3. 公共编排形状

### 3.1 标的绑定

`CrossPeriodInstrumentBinding` 只包含调用方提供的 `instrumentKey` 和 `scopeKey`。
协调器必须校验 `scopeKey` 与 Workspace 的 `drawings.scopeKey`、`binding.scopeKey`
完全一致。不得从 `scene.symbol.ticker`、名称或其他字段推断或兜底。

### 3.2 周期 Scene 加载端口

`CrossPeriodSceneLoader` 接收显式 binding 与目标 Period，返回完整、可独立通过现有
Scene parser 的 `ChartScene` 或 `TimeSeriesScene`。协调器只调用
`DrawableWorkspaceRuntime.replaceScene()`；不能解析行情、修改数据或直接访问引擎。

### 3.3 Drawing 持久化端口

`CrossPeriodDrawingPersistencePort` 接收 Runtime 产生的候选 DrawingDocument、候选
Workspace、canonical hash、requestId、幂等键和当前 revision。宿主成功写入后必须返回
完全相同的 canonical hash 与新 revision；协调器只有在哈希严格相等时调用
`commitDrawingChange()`，否则调用 `rejectDrawingChange()` 恢复 confirmed 状态。

owner、权限、审计和数据库事务由端口实现通过闭包或自身依赖完成，不进入公共 DTO，
也不改变 Drawing canonical hash。

### 3.4 编排状态

协调器状态固定为：

- `ready`：允许发起周期切换；
- `switching-period`：正在加载并应用候选 Scene；
- `persisting-drawing`：正在持久化一个 host-confirmed Drawing 候选；
- `terminal-error`：持久化成功后本地提交失败或候选无法恢复，只允许销毁并重载；
- `destroyed`：已解除事件订阅，不再接受操作。

周期加载期间若仍收到 Drawing 候选，必须拒绝候选并保持 confirmed；持久化期间拒绝周期
切换。业务 pending UI 通过独立编排事件获知状态，不能修改 Workspace Runtime 事件协议。

## 4. 依赖顺序、文件范围与验证门禁

### Task 0：修复公共 Scene 重投影事务

文件范围：

- `packages/web-runtime/src/drawing/session-controller.ts`
- `packages/web-runtime/src/drawing/workspace-runtime.ts`
- `packages/web-runtime/test/drawing-session-controller.spec.ts`
- `packages/web-runtime/test/workspace-runtime.spec.ts`

门禁与完成标准：

- 切换成功后后续候选按新 Scene 投影；
- `reprojecting` 期间 mutation 被拒绝；
- Adapter 替换失败后旧 Scene、confirmed Drawing、选择和投影 Scene 不变；
- 不改变 `replaceScene()` 的同步 API，不触碰两个 Adapter 的 Chart 所有权。

### Task 1：实现 scope 与持久化编排

文件范围：

- `packages/web-runtime/test/cross-period-coordinator.spec.ts`

门禁与完成标准：

- scope 不一致在订阅或副作用发生前失败；

- 协调器事件与 Workspace Runtime 事件协议严格分离。

## 5. 禁止事项

- 不新增 `InstrumentDrawingDocument`、`InstrumentDrawing`、`ChartWorkspaceDocument` 或
  承担画线权威的 `InstrumentDrawingRuntime`；
- 不访问 KLineCharts Chart、Adapter 私有状态或业务 Canvas；
- 不复制时间桶、几何、反投影或 Canonical 实现；
- 不从 ticker/name 推导 scopeKey，不以其他业务字段兜底；
- 不让 TimeSeriesScene 绕过 v1 线性轴边界，也不裁剪其 22 种 Drawing；
- 不把 owner、revision、权限、审计或幂等信息写入 DrawingDocument；
- 不执行未经授权的 `git add`、`commit`、`push`、切分支或创建 worktree。

## 7. 独立审查闭环

独立审查已修复以下 Critical/Important：

1. **Critical**：修复 `replaceScene()` 后 Controller 仍使用初始 Scene 投影的问题，并补齐
   `reprojecting` 与引擎 mutation 门。
2. **Important**：轴缩放也纳入异步 Scene 投影事务，避免 Runtime Scene 与 Controller
   投影 Scene 分叉。
3. **Important**：删除协调器自建的 Runtime 事件协议和 CrossPeriod 周期别名，普通宿主
   编排事件直接复用 Schema `Period`，不形成第二权威。
4. **Important**：幂等键不再包含 Runtime 临时 requestId，改为稳定的 scopeKey 与
   canonical hash。
5. **Important**：持久化成功后 Runtime commit 失败、候选恢复失败均进入 destroy-only
   终止态；终止态允许幂等销毁，revision 不提前推进。
6. **Important**：原 Legacy 门禁对整个声明文件做 hash，无法区分破坏性变更与增量公共
   API。现改为锁定旧 API 投影的原 hash，并由候选包消费编译独立验证新增 API；旧声明
   仍不可改名、删除或收窄。

最终复核未发现遗留 Critical 或 Important。
