# 全图表统一画图能力实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项实施；所有步骤使用复选框跟踪。未经用户另行授权，不得执行 `git add`、`git commit`、`git push`、切分支或创建 worktree。

**Goal:** 以《全图表统一画图能力技术方案》为唯一上位架构，在保持现有 Client API 完全兼容的前提下，让 `ChartScene`、`TimeSeriesScene` 以及未来正式交互式图表类型通过同一 `DrawingDocument`、`DrawableWorkspaceDocument`、公共 Runtime 能力和标准工具栏完整支持现有 22 种 Drawing；同一 OHLCV `ChartScene` 可在不重建 Chart、不迁移 Drawing 的情况下切换蜡烛/OHLC 与固定使用 `close` 的 `area` 收盘价折线。

**Architecture:** Scene 继续只表达被展示的数据，`DrawingDocument` 成为新 Workspace 模式下唯一画线事实，`DrawableWorkspaceDocument` 负责显式组合 Scene、Drawing 和坐标绑定。`DrawableWorkspaceRuntime` 通过 `DrawingSessionController`、`DrawingProjectionService` 和由现有两个 Scene Adapter 实现的 `DrawingEnginePort` 完成交互；公共 Projection Service 承担全部时间/几何算法，两个场景 policy 只解析 pane/axis/precision/scale 绑定。两个 Adapter 分别独占自己的 KLineCharts `Chart`，纯投影策略和公共 Runtime 永不访问引擎。`ChartScene` 主序列展示切换由同一 KLine Adapter 原子更新引擎样式，不进入 `TimeSeriesScene`。Legacy `ChartScene.overlays` 模式与 Workspace 模式在入口、状态、事件和导出制品上严格隔离。

**Tech Stack:** TypeScript 5.9、JSON Schema Draft 2020-12、AJV standalone、RFC 8785 Canonical JSON、KLineCharts 10.0.0、`@js-temporal/polyfill` 0.5.1、Vitest 4.1、Playwright 1.61、Node.js 22/24、Python 3.11–3.14、`jsonschema`、`rfc8785`、npm workspaces。

## 1. 权威边界复核结论

### 1.1 被上位方案取代的重复定义

| 跨周期文档中的旧权威 | 新唯一权威 | 处理规则 |
| --- | --- | --- |
| `InstrumentDrawingDocument` | `DrawingDocument` | 删除重复接口、几何和 Canonical 定义；跨周期只提供稳定标的到 `scopeKey` 的业务映射 |
| `InstrumentDrawing` | `Drawing` | 删除金融专属 Drawing 联合类型；全部 22 种几何由公共 Drawing Schema 唯一定义 |

### 2.1 `DrawingDocument` 与 22 种 `Drawing`

```ts
interface DrawingDocument {
  schema: '@baron1996/drawing-document';
  version: 1;
  scopeKey: string;
  coordinateSystem: {
    timezone: string;
    valueAxes: Array<{
      paneRole: string;
      yAxisRole: string;
      valuePrecision: number;
    }>;
  };
  drawings: Drawing[];
  metadata: JsonObject;
}

interface DrawingBase {
  id: string;
  groupId?: string;
  target: {
    paneRole: string;
    yAxisRole: string;
  };
  visible: boolean;
  locked: boolean;
  zLevel: number;
  mode: 'normal' | 'weak_magnet' | 'strong_magnet';
  styles: DrawingStyles;
  metadata: JsonObject;
}

interface DrawingTimeAnchor {
  timestamp: number;
  granularity: DrawingPeriod;
}

interface TimeValuePoint extends DrawingTimeAnchor {
  value: number;
}
```

约束：

- `Period` 不是 Drawing 新建的时间模型。Task 2 必须把当前 `ChartScene` 与 `TimeSeriesScene` 完全相同的 period 形状提升为 `common.schema.json#/$defs/period` 的唯一 Schema 权威；两个旧 Scene 与新 Drawing Schema 都只 `$ref` 该定义。生成器采用“单一内部共享结构、三个稳定公共名称”：旧 Chart 类型继续导出 `Period`，旧 TimeSeries 类型继续导出 `TimeSeriesPeriod`，Drawing 新增 `DrawingPeriod`；三者结构同源但包根无重名导出。该整理不得改变旧 Scene 可接受的 JSON、旧导入路径、生成类型名称、canonical bytes、hash 或错误语义。
- `scopeKey` 是调用方提供的稳定、非空、不透明范围键；通用层不解释它是金融标的、统计主题还是其他业务对象。
- `coordinateSystem.timezone` 使用现有 IANA timezone 约束。`coordinateSystem.valueAxes` 以 `(paneRole, yAxisRole)` 唯一标识稳定值轴，每项 `valuePrecision` 范围为 `0..16`；数组必须按 `paneRole`、`yAxisRole` 词法升序且无重复，保证同一语义只有一种 canonical 顺序。
- Drawing 只保存时间和值等业务坐标，不保存像素、KLineCharts 内部 ID、Canvas 状态、派生量度文本或可执行回调。
- `paneRole`、`yAxisRole` 是稳定语义角色。v1 的 `yAxisRole` 只允许 `primary`：K 线 `paneRole` 支持 `candle` 和 `indicator:<stable-indicator-id>`，但 indicator 只有绑定其 pane 的 primary axis 时才可作为 Drawing target；时间序列只支持 `time-series` / `primary`。原因是 KLineCharts 10.0.0 的 Overlay 契约只接受 `paneId`，不能显式绑定 `yAxisId`。每个 Drawing target 必须精确命中一个 `coordinateSystem.valueAxes` 条目；additional axis 目标整体返回 `DRAWING_TARGET_INVALID`，不得用主轴数值换算、像素换算或隐藏 Overlay 模拟。
- `DrawingStyles` 通过公共 Schema `$defs` 复用现有 line/fill/text 语义，不能复制另一套颜色、线型或文本样式定义。
- Workspace 新模式的值坐标允许有限正数、零和负数；线性轴必须完整支持。对数轴投影遇到非正值时以稳定投影错误拒绝该次操作。Legacy `ChartScene.priceMeasurement` 的既有校验不因新模式而放宽。
- 所有 geometry 均 `additionalProperties: false`；`brush.points` 为 `2..256`；所有 timestamp 为 safe integer，所有 value 为有限数值并按该 Drawing target 命中的 `valueAxes.valuePrecision` 规范化。唯一数值规则复用现有 `normalizePriceValue` 的精确十进制语义：最接近、恰好半值远离零（ties-away-from-zero）、`-0` 输出为 `0`；禁止 `Math.round`、`toFixed`、二进制定点乘除或引擎显示文本参与权威值计算。Runtime 创建/反投影先规范化，外部导入的 DrawingDocument 若任一 value 不等于规范化结果则语义校验拒绝，不在 parser/canonical 阶段静默改写。

22 种类型与唯一几何矩阵：

| Drawing type | `geometry` |
| --- | --- |
| `horizontalStraightLine`、`priceLine` | `{ value }` |
| `simpleTag` | `{ value, text }` |
| `verticalStraightLine` | `{ time }` |
| `horizontalRayLine`、`horizontalSegment` | `{ value, startTime, endTime }` |
| `verticalRayLine`、`verticalSegment` | `{ time, startValue, endValue }` |
| `rayLine`、`segment`、`straightLine`、`fibonacciLine` | `{ points: [TimeValuePoint, TimeValuePoint] }` |
| `priceChannelLine`、`parallelStraightLine` | `{ points: [TimeValuePoint, TimeValuePoint, TimeValuePoint] }` |
| `brush` | `{ points: [TimeValuePoint, TimeValuePoint, ...TimeValuePoint[]] }` |
| `simpleAnnotation`、`callout`、`text` | `{ point, text }` |
| `crossLine` | `{ point }` |
| `rectangle`、`arrow`、`priceMeasurement` | `{ start, end }` |

必须有编译期双向穷尽断言，保证 `Drawing['type']` 与现有 `SceneOverlay['type']` 各自 `Exclude` 后均为 `never`；这只证明工具集合一致，不允许把两种权威文档自动互转或合并。

### 2.2 `DrawableWorkspaceDocument`

```ts
interface DrawableWorkspaceDocument {
  schema: '@baron1996/drawable-workspace';
  version: 1;
  runtime: {
    engine: 'klinecharts';
    engineVersion: '10.0.0';
    workspaceRuntimeVersion: '1.0.0';
  };
  scene:
    | { kind: 'chart'; document: ChartScene }
    | { kind: 'time-series'; document: TimeSeriesScene };
  drawings: DrawingDocument;
  binding: {
    scopeKey: string;
    timezone: string;
    valueAxes: Array<{
      paneRole: string;
      yAxisRole: string;
      valuePrecision: number;
    }>;
  };
  metadata: JsonObject;
}
```

根关系校验：

1. `binding.scopeKey/timezone/valueAxes` 必须分别与 `drawings` 对应字段精确相等；两处 `valueAxes` 都按同一稳定顺序存储。
2. `chart` 分支要求 `scene.document.overlays.length === 0`、`chart.timezone === binding.timezone`。`candle` target 的 precision 必须等于 `symbol.pricePrecision`；`indicator:<id>` target 必须解析到唯一 `SceneIndicator`，其 `yAxisId` 必须指向所属 pane 的唯一 primary axis，precision 必须等于该 indicator 自己的 `precision`，不能取 symbol 精度替代。additional axis indicator target 整体拒绝。
3. `time-series` 分支要求 `chart.timezone === binding.timezone`，所有 series 已按旧语义共享 unit/precision，唯一 `time-series` / `primary` value-axis binding 的 precision 等于共享 series precision。
4. Workspace 只接受声明 Scene 分支可解释的 `target`；不认识的 pane/axis role 整体拒绝，不自动改到主窗格或其他轴。
5. Workspace API 收到 raw `ChartScene`/`TimeSeriesScene` 必须拒绝；旧 Scene API 收到 Workspace 必须按原 Schema 拒绝。
6. `ChartScene.overlays` 与 `DrawingDocument.drawings` 不合并、不去重、不取并集；两份非空权威是明确错误。

### 2.3 公共 Runtime 边界

`DrawingRuntimeCapability` 只暴露场景无关的 Drawing 操作：开始创建、查询公共视图、选中、命中测试、坐标投影、样式/文本修改、删除请求、事件订阅和销毁。它不提供 Scene/Workspace 导出，也不暴露 `Chart`。

主序列展示输入冻结为：

```ts
type MainSeriesPresentation =
  | { readonly type: 'candle_solid' | 'candle_stroke' | 'candle_up_stroke'
      | 'candle_down_stroke' | 'ohlc' }
  | {
      readonly type: 'area';
      readonly value: 'close';
      readonly line: {
        readonly color: 'rgba(41, 98, 255, 1)';
        readonly size: 2;
      };
      readonly backgroundColor: 'rgba(0, 0, 0, 0)';
      readonly smooth: false;
      readonly pointVisible: false;
    };
```

`RuntimeCapabilityDescriptor` 是只读能力描述，至少包含：

```ts
interface RuntimeCapabilityDescriptor {
  readonly drawingTypes: readonly DrawingType[]; // 两种 Workspace Scene 均为完整 22 种
  readonly valueAxis: {
    readonly supportedScales: readonly ('linear' | 'logarithmic')[];
    readonly activeScale: 'linear' | 'logarithmic';
    readonly mutable: boolean;
  };
  readonly exportArtifact: {
    readonly kind: 'chart-scene' | 'drawable-workspace';
    readonly mediaType: 'application/json';
    readonly defaultFileName: string;
  };
  readonly mainSeriesPresentation: null | {
    readonly presentations: readonly MainSeriesPresentation[];
    readonly activeType: 'candle_solid' | 'candle_stroke' | 'candle_up_stroke'
      | 'candle_down_stroke' | 'ohlc' | 'area';
    readonly mutable: boolean;
  };
  readonly hostActions: readonly { actionId: string; label: string }[];
}
```

工具栏依赖的完整结构类型为 `DrawingRuntimeCapability & RuntimeAuxiliaryCapability`。后者固定提供 `getRuntimeCapabilityDescriptor({ hostActions? })`、`setValueAxisScale(scale)`、`setMainSeriesPresentation(presentation)`、`exportArtifact()` 和 `requestHostAction()`；主序列方法返回 `{ activeType }` 纯数据快照，供工具栏更新一次性 Descriptor 对应的当前选中态，不要求重新识别 Runtime；`exportArtifact()` 返回与 Descriptor `kind` 一致的 canonical bytes、mediaType 和文件名。`StandardToolbarOptions.hostActions` 为保持旧调用兼容，只能作为 `getRuntimeCapabilityDescriptor()` 的通用输入，由 Runtime 生成一次有效 Descriptor；工具栏自身不合并能力、不判断 Runtime 类型。重复 actionId 明确拒绝。新增 `mainSeriesPresentationControl?: 'hidden' | 'enabled'` 是显式 UI 开关：旧调用省略时严格保持既有 DOM；需要切换的 Legacy/Workspace 调用方必须显式传 `enabled`，工具栏随后只消费 Descriptor，不判断 Scene。

`setMainSeriesPresentation()` 的输入必须是完整 discriminated union：旧五种 bar/OHLC 类型只携带 `type`；`area` 必须携带 Schema 要求的显式 line style，值来源固定为 `value: 'close'`，line color 固定为 `rgba(41, 98, 255, 1)`、line size 固定为 `2`，填充固定透明、point 固定隐藏、smooth 固定关闭；这些值在 TypeScript 中都是字面量，在 JSON Schema 中都是 `const`。Descriptor 的 `presentations` 保存工具栏可原样提交的完整值，其中版本化 `STANDARD_CLOSE_LINE_PRESENTATION` 就是上述唯一对象；这是正式产品配置，不读取其他字段或引擎默认值。非 `area` Scene 不保留 `area` 专属配置，保证 active presentation 只有一种 canonical 表示。

- Legacy `KLineSceneRuntime` 描述 `chart-scene` 导出和线性/对数轴能力，继续实现既有 API。
- Legacy `KLineSceneRuntime` 和 `DrawableWorkspaceRuntime` 的 `chart` 分支描述非空 `mainSeriesPresentation`；`time-series` v1 固定为 `null`，调用切换方法返回稳定 unsupported error。
- `DrawableWorkspaceRuntime` 描述 `drawable-workspace` 导出；其 `chart` 分支可声明线性/对数，`time-series` v1 固定 `supportedScales: ['linear']`、`activeScale: 'linear'`、`mutable: false`。
- 工具栏只能读取 Descriptor 和调用公共能力，不允许导入/判断 `KLineSceneRuntime`、`TimeSeriesRuntime` 或 Scene schema 字符串。

## 6. 22 种 Drawing 完成交互验收定义

“支持”不能只以 Schema 能解析或引擎能显示为准。每种 Drawing 在 `ChartScene` Workspace 和 `TimeSeriesScene` Workspace 中都必须满足以下共同完成标准：

1. 工具栏有唯一按钮并能启动创建；点击/拖动步数与 Task 1 校准结果一致。
2. 完成创建后形成严格 `Drawing`，不把 projected dataIndex、paneId、yAxisId、像素或派生显示字段写入文档。
3. 导出、销毁、重新创建 Runtime 后视觉和 canonical 几何恢复。
4. 可通过公共能力选择、命中、查询；locked Drawing 不接受 mutation。
5. 支持整体移动；支持该类型定义的锚点编辑；`brush` 中间点是否逐点可编辑以 Task 1 的正式能力矩阵冻结，但不得影响整体移动、样式和持久化。
6. line/fill/text styles 能恢复；标准工具栏至少覆盖 solid/dashed/dotted、线宽、颜色；文本类支持创建和选中后文本修改。
7. 删除走统一 candidate/confirm 链，reject 恢复 before。
8. Scene 数据替换只触发重投影，不改变 confirmed Drawing canonical bytes。
9. 当前数据范围外只是不渲染，Drawing 仍保留；重新进入范围后恢复。
10. 两场景事件 envelope、operation、before/candidate、sequence 和错误语义一致。
11. ChartScene 在创建中和创建后执行 candle→area→candle 时复用同一 Chart/Overlay，会话、锚点、选择与 Drawing canonical 不变；area 固定读取 close。

必须逐类覆盖：

```text
horizontalRayLine, horizontalSegment, horizontalStraightLine,
verticalRayLine, verticalSegment, verticalStraightLine,
rayLine, segment, straightLine, priceLine,
priceChannelLine, parallelStraightLine, fibonacciLine, brush,
simpleAnnotation, simpleTag, rectangle, arrow, crossLine,
callout, text, priceMeasurement
```

## 7. 关键兼容边界与禁止事项

### 7.1 Legacy `ChartScene.overlays` 与 Workspace

- Legacy 入口永远只以 `ChartScene.overlays` 为权威；Workspace 入口永远只以 `DrawingDocument.drawings` 为权威。
- Legacy 适配公共工具栏能力只是操作门面复用，不产生 DrawingDocument、不改变 export artifact、不构成自动迁移。
- Workspace `chart` Scene 内 overlays 必须为空；不允许“新文档优先”“旧 overlays 补充”“按 ID 合并”或任何其他 fallback。

### 7.2 导出制品

- Legacy toolbar/Runtime/HTML/CLI/Python 导出 `ChartScene`，保留 `__BARON_KLINE_SCENE__.exportScene()`。
- Workspace toolbar/Runtime/HTML/CLI/Python 导出 `DrawableWorkspaceDocument`，使用 `exportWorkspace()` 和 `__BARON_DRAWABLE_WORKSPACE__`。
- 公共工具栏共享 UI，不共享制品猜测；artifact kind 只来自 Descriptor。

### 7.3 两个 Adapter 与纯策略

- `KLineChartsSceneAdapter` 和 `TimeSeriesChartsAdapter` 分别持有自己的私有 `#chart`；任何公共接口不得返回 Chart、Overlay 实例、内部 pane/yAxis/overlay ID。
- `DrawingSessionController` 只能调用 `DrawingEnginePort`；`DrawingProjectionService` 和两个 policy 只能处理纯数据。
- `DrawingProjectionService` 唯一实现时间、22 几何和反投影算法；两个 policy 只能做 pane/axis/precision/scale binding，不得形成两套投影核心。
- TimeSeries Drawing 绑定公共数值轴，不绑定具体 series；series null/隐藏不改变 Drawing value。
- v1 Drawing 的 `yAxisRole` 只允许 `primary`；K 线 indicator 只有位于 pane primary axis 时可成为 target。additional axis 不做主轴换算、像素换算或不可见的自动改绑。

### 7.4 ChartScene 主序列展示

- candle/OHLC/area 都属于同一 `ChartScene`；area 只能使用 OHLCV close，不构造或切换到 `TimeSeriesScene`。
- `MainSeriesPresentationPort` 与 `DrawingEnginePort` 分离，但都只能由现有 `KLineChartsSceneAdapter` 实现；任何切换不得创建第二个 Chart。
- 主序列展示切换不进入 Drawing candidate/commit，不重投影、不迁移、不重建 Overlay；切换瞬间 DrawingDocument canonical bytes/hash 不变。
- 主序列切换以 `getStyles()` 完整快照、写后读和 Overlay/选择快照校验实现原子语义；apply 失败必须完整回滚，回滚失败进入只能销毁的终止错误态，绝不重建 Chart。
- 工具栏只有在显式 options 启用且 Descriptor 提供完整 presentation 时才展示控件；不得从其他颜色字段或引擎默认值产生 area 样式。

### 7.5 旧 Client API

- 旧 TypeScript/Python symbol 不删除、不重命名、不改变参数顺序、返回类型或事件字段。
- 新功能只通过新增 parser、Workspace factory、Workspace render/CLI/Python API 暴露。
- 旧 raw Scene API 不识别 Workspace；新 Workspace API 不识别 raw Scene。
- 旧 fixture、hash、HTML bridge、PNG baseline 和 CLI bytes 是回归门，不通过就不能发布。

## 8. 停止条件

以下任一情况出现时立即停止对应阶段并请求用户重新确认，不得自行设计替代方案：

1. KLineCharts 10.0.0 无法在本仓库正式 Adapter/Overlay 边界内完成任一类型的创建、恢复、选择、编辑、删除或 dispose。
2. KLineCharts 10.0.0 无法在同一 Chart/Overlay 会话内完成任一 Drawing 创建中的 candle↔area 切换，或必须重建 Runtime/Adapter/Chart 才能切换。
3. 实现要求新增第二图表引擎、业务 Canvas、复制源码、实时源码依赖或 Python 独立绘图实现。
4. 必须让纯投影策略、Controller、Toolbar 或业务调用方取得 KLineCharts Chart。
5. 必须合并非空 `ChartScene.overlays` 与 `DrawingDocument.drawings`，或必须让旧导出自动变成 Workspace。
6. TimeSeriesScene 只有裁剪 Drawing 类型才能交付，或必须用某条 series 的值替代 Drawing value。
7. Node/Python canonical bytes/hash 或错误序列无法一致。
8. 旧 Client API、旧 fixture/hash、旧 HTML/PNG/CLI/Python 行为无法保持。
9. 实施文件与其他 Session 的并行修改发生无法安全拆分的重叠。
10. 产品要求对同一 pane 的 additional axis 直接创建 Drawing，而当前发布的 KLineCharts Overlay API 仍不能显式绑定 `yAxisId`。
