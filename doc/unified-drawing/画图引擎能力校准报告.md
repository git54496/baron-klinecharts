# 画图引擎能力校准报告

> 本报告是《全图表统一画图能力实施计划》Task 1 的产物，记录 KLineCharts 10.0.0 在两种数据载体上对 22 种 Drawing 的原始引擎可表达性证据。报告只校准原始引擎公共 API，不宣称正式 Adapter 契约已完成；正式 `DrawingEnginePort` 的 restore/create/select/edit/delete 全矩阵由 Task 5 验收。

## 1. 范围与方法

- 引擎：`klinecharts@10.0.0`（精确版本，仓库锁定）。
- 运行环境：Chromium headless，真实浏览器事件，Playwright 驱动；测试不导入 `KLineChartsSceneAdapter`、`TimeSeriesChartsAdapter` 或任何未实现的端口。
- Harness 边界：只调用引擎公共 API（`init`、`createOverlay`、`overrideOverlay`、`removeOverlay`、`getOverlays`、`setStyles`、`getStyles`、`createYAxis`、`getYAxes`、`convertToPixel`、`convertFromPixel`、`subscribeAction`、`dispose`），不读取私有字段、不修改引擎产物。
- 测试文件：`packages/klinecharts-adapter/test/drawing-engine-capability.browser.spec.ts`。
- 数据载体：
  - K 线载体：`tests/fixtures/scenes/all-overlays.json`（补齐 `priceMeasurement` 后为 22 种），`candle_pane`，linear 轴。
  - TimeSeries carrier：同一时间轴与公共数值轴，3 根数据；补充零值/负值载体（`0`、`-3.2`、`12.74`）。

## 2. 结论摘要

1. 22 种 Drawing 在 K 线和 TimeSeries 两种载体上均能 `createOverlay`、`overrideOverlay`、`removeOverlay`，且导出前可恢复几何。
2. 22 种 Drawing 均能在第一个有效交互之后、完成之前原地切换主序列 `candle → area`，继续完成交互后再切回 `candle_solid`；Chart、Overlay、已取得锚点、事件订阅全程不变。
3. `OverlayCreate` 类型没有 `yAxisId`（编译期断言成立）；运行时传入 `yAxisId` 额外字段会被对象保留，但引擎渲染固定使用 pane 默认轴（源码：overlay 绘图经 `pane.getYAxisComponentById()` 无参调用）。同一 pane 创建 additional 轴后其范围为 `0..0`，投影为非有限值，无法作为 Drawing target。**v1 primary-only 边界成立，无需修改契约。**
4. K 线、TimeSeries 两个容器生命周期相互独立；`dispose` 后容器清理，同一容器可重新 `init`。
5. 校准过程中发现并修复一个产品 Overlay 缺陷：TimeSeries 上 `priceMeasurement` 起点为零时原派生函数抛错，现按产品语义只显示绝对变化、百分比位置显示 `—`（见第 7 节）。
6. 未触发实施计划的任何停止条件；Task 2 可以开始。

## 4. 原始引擎事件与回调

校准确认以下 `OverlayCreate` 回调在 22 种类型上可用：`onDrawEnd`、`onPressedMoveStart`、`onPressedMoving`、`onPressedMoveEnd`、`onSelected`、`onDeselected`、`onRemoved`。创建交互完成以 `onDrawEnd` 触发且 `currentStep === -1` 为准。

## 5. 公开坐标 API

- `convertToPixel(points, { paneId, yAxisId, absolute })` / `convertFromPixel(coordinates, filter)` 对 primary 轴返回有限坐标；对无有效范围的 additional 轴返回 `null` 或非有限值。
- `getYAxes({ paneId })` 返回 pane 上全部数值轴，primary 为默认轴。

## 6. primary/additional 双轴校准

- 同一 `candle_pane` 上通过 `createYAxis` 可创建 additional 数值轴，但 22 种类型全部只能以 primary 为有效 target。
- 编译期证据：`OverlayCreate` 不存在 `yAxisId` 字段（`drawing-engine-capability.browser.spec.ts` 内类型断言）。
- 运行时证据：向 `createOverlay` 传入 `yAxisId` 额外字段后，overlay 对象保留该字段，但其默认投影与未传字段的 overlay 完全一致；引擎渲染仍走 pane 默认轴。
- additional 轴在真实 fixture 下范围为 `0..0`，投影为非有限值；即使尝试在其上挂载 indicator 也未形成有效范围。结论：v1 只能绑定 primary，不需要主轴数值换算或像素换算 fallback。

## 7. 校准期间修复的产品 Overlay 缺陷

TimeSeries 线性轴允许零值，`priceMeasurement` 起点为零时原 `derivePriceMeasurementDisplay` 抛 `SCENE_SCHEMA_INVALID`，导致画线无法渲染。已在 `packages/klinecharts-adapter/src/extensions/price-measurement.ts` 修复：起点为零时只显示绝对变化，百分比位置显示 `—`（`percentageChange` 为 `null`），派生显示字段仍不进入任何持久化 DTO；非有限数与越界精度仍拒绝。对应单测同步更新。

## 8. 生命周期与隔离

- K 线、TimeSeries 各自独立容器/Chart；`candle → area → candle` 往返前后 Chart 引用、Overlay id、锚点、事件订阅保持有效。
- 一个容器 `dispose` 后不清理另一个容器的 Chart 与 overlay；`dispose` 后容器无残留子节点，同一容器可重新 `init`。
